# MoCap Studio v0.3 — полное тело / Android

Проект использует HTML5 + Three.js + MediaPipe Pose (33 ориентира) в оболочке Capacitor. Приложение обрабатывает видео **локально на устройстве**. Версия v0.3 использует изображения пользователя: квадратный сурикат — **иконка Android**, вертикальный постер — **заставка**.

## Исправления v0.3

- Отдельное сопоставление левой/правой руки и ноги, плеча, локтя, кисти, бедра, колена, стопы; голова, шея, грудь, таз.
- Переключатель зеркала меняет **только CSS-отображение видео**. Не меняет MediaPipe, кости или экспорт. При потере конечности она остаётся в последней позе, не копируя другую.
- Android использует `https://localhost` через Capacitor; нативный плагин явно запрашивает Android CAMERA перед `getUserMedia`. Из `content://` скачанный HTML не открывать.
- Экспорт GLB и JSON записывает локальные вращения 19 основных костей полного тела. **Без** перемещения корня в пространстве и без отслеживания пальцев. 3D-манекен — тестовый.
- Русский интерфейс, офлайн-модель MediaPipe, заставка и иконка.

## Сборка

GitHub Actions → **MoCap Studio Android APK** → успешный запуск → **Artifacts: MoCap-Studio-Android-APK**. Это debug APK. GitHub CI ставит npm, локальную модель, Android-манифест, Java-плагин, иконки и собирает `assembleDebug`.

Локально: `npm install`, `bash scripts/get-model.sh`, `npm test`, `npm run build`. Для Android нужны Java 21 + Android SDK: `npx cap add android`, `python3 scripts/camera-manifest.py`, `bash scripts/android-branding.sh`, `npx cap sync android`, затем `cd android && ./gradlew assembleDebug`.

**Важно:** автоматические тесты проверяют логику сторон и сборку, но фактическое качество трекинга и разрешения WebView нужно подтвердить на устройстве. Снимай человека целиком, при достаточном освещении. Нестандартные скелеты требуют ретаргетинга в Animation Studio.

## v0.4 — импорт своего GLB и меньшая задержка

- В панели 3D-персонажа: **«＋ Загрузить GLB»**. Файл должен быть самодостаточным бинарным GLB, содержать реальный `SkinnedMesh` и гуманоидный скелет. Непривязанный меш или несовместимый скелет приложение показывает как ошибку — сначала привяжи его в Animation Studio. Предел одного GLB — 90 МБ, но на старом Android даже меньшая сложная модель может расходовать много памяти.
- Загрузка оставляет текущую камеру или видео и привязывает распознанные движения к совместимым костям модели, не переписывая их имена. Данные камеры не зеркалируются (отражается только видео). При загрузке другого персонажа старая запись очищается **после подтверждения**.
- После записи **«Экспорт GLB»** сохраняет выбранную модель с анимацией; при использовании стандартного манекена — манекен с анимацией. Сохранение модели с анимацией в сторонних редакторах проверять повторной загрузкой. Результат зависит от сходства костных систем, rest-pose, направления суставов и качества skin weights. **Это базовый ретаргетинг, а не универсальный AutoRig:** нестандартные персонажи могут потребовать ручной поправки в Animation Studio.
- Для меньшего отставания: исходный лимит 10 FPS заменён адаптивным с нижним интервалом около 32 мс, исходное сглаживание снижено с 45% до 12%, разрешение камеры по умолчанию 480×360 (30 FPS), облегчена 3D-отрисовка, GPU MediaPipe с автоматическим CPU fallback при невозможности инициализировать GPU. На экране показывается время одной операции распознавания в миллисекундах. **Задержка всё равно зависит от камеры и железа; фактическая производительность проверяется на устройстве.**
- Иконка и splash с согласованным сурикатом, корректный Android CAMERA-плагин и офлайн модель MediaPipe сохранены из v0.3.
