## История версий

### v0.3 — полное тело / Android

Проект использует HTML5 + Three.js + MediaPipe Pose (33 ориентира) в оболочке Capacitor. Приложение обрабатывает видео **локально на устройстве**. Версия v0.3 использует изображения пользователя: квадратный сурикат — **иконка Android**, вертикальный постер — **заставка**.

## Исправления v0.3

- Отдельное сопоставление левой/правой руки и ноги, плеча, локтя, кисти, бедра, колена, стопы; голова, шея, грудь, таз.
- Переключатель зеркала меняет **только CSS-отображение видео**. Не меняет MediaPipe, кости или экспорт. При потере конечности она остаётся в последней позе, не копируя другую.
- Android использует `https://localhost` через Capacitor; нативный плагин явно запрашивает Android CAMERA перед `getUserMedia`. Из `content://` скачанный HTML не открывать.
- Экспорт GLB и JSON записывает локальные вращения 19 основных костей полного тела. **Без** перемещения корня в пространстве и без отслеживания пальцев. 3D-манекен — тестовый.
- Русский интерфейс, офлайн-модель MediaPipe, заставка и иконка.

## Сборка

GitHub Actions → **MoCap Studio Android APK** → успешный запуск → **Artifacts: MoCap-Studio-Android-APK**. Это debug APK. GitHub CI ставит npm, локальную модель, Android-манифест, Java-плагин, иконки и собирает `assembleDebug`.

Локально: `npm install`, `bash scripts/get-model.sh`, `npm test`, `npm run build`. Для Android нужны Java 21 + Android SDK: `npx cap add android`, `python3 scripts/camera-manifest.py`, `bash scripts/android-branding.sh`, `npx cap sync android`, затем `cd android && ./gradlew assembleDebug`.

**Важно:** автоматические тесты проверяют логику сторон и сборку, но фактическое качество трекинга и разрешения WebView нужно подтвердить на устройстве. Снимай человека целиком, при достаточном освещении. Нестандартные скелеты требуют ретаргетинга в Animation Studio.

## v0.4 — импорт своего GLB и меньшая задержка

- В панели 3D-персонажа: **«＋ Загрузить GLB»**. Файл должен быть самодостаточным бинарным GLB, содержать реальный `SkinnedMesh` и гуманоидный скелет. Непривязанный меш или несовместимый скелет приложение показывает как ошибку — сначала привяжи его в Animation Studio. Предел одного GLB — 90 МБ, но на старом Android даже меньшая сложная модель может расходовать много памяти.
- Загрузка оставляет текущую камеру или видео и привязывает распознанные движения к совместимым костям модели, не переписывая их имена. Данные камеры не зеркалируются (отражается только видео). При загрузке другого персонажа старая запись очищается **после подтверждения**.
- После записи **«Экспорт GLB»** сохраняет выбранную модель с анимацией; при использовании стандартного манекена — манекен с анимацией. Сохранение модели с анимацией в сторонних редакторах проверять повторной загрузкой. Результат зависит от сходства костных систем, rest-pose, направления суставов и качества skin weights. **Это базовый ретаргетинг, а не универсальный AutoRig:** нестандартные персонажи могут потребовать ручной поправки в Animation Studio.
- Для меньшего отставания: исходный лимит 10 FPS заменён адаптивным с нижним интервалом около 32 мс, исходное сглаживание снижено с 45% до 12%, разрешение камеры по умолчанию 480×360 (30 FPS), облегчена 3D-отрисовка, GPU MediaPipe с автоматическим CPU fallback при невозможности инициализировать GPU. На экране показывается время одной операции распознавания в миллисекундах. **Задержка всё равно зависит от камеры и железа; фактическая производительность проверяется на устройстве.**
- Иконка и splash с согласованным сурикатом, корректный Android CAMERA-плагин и офлайн модель MediaPipe сохранены из v0.3.

## v0.5 — проверка уменьшенной задержки для APK после №6

- MediaPipe Pose перенесён в Web Worker на CPU, чтобы синхронный детектор не блокировал 3D-отрисовку. На Android WebView без нужных API сохраняется совместимый режим main-thread GPU/CPU; он может быть медленнее.
- В фоне не создаётся очередь старых видеокадров: пока текущий ImageBitmap распознаётся, новый не отправляется. После готовности берётся последний кадр камеры.
- При перезапуске камеры/видео результаты старого источника отбрасываются; проблемы и зависания worker вызывают переключение на совместимый режим.
- Отображаются отдельное время инференса и возраст обработанного кадра (без задержки сенсора и декодирования видео). Замер не равен полной задержке от движения пользователя.
- Стандартная камера 3D смотрит на модель спереди. При включённом зеркале 3D-просмотр и видео согласованы визуально, но данные скелета и экспорт не зеркалируются.
- Концевые кости кистей теперь получают ориентацию от landmarks запястье→ладонь, даже если у шаблонного манекена нет дочерней кости.
- Новые регрессионные тесты контролируют отсутствие очереди устаревших кадров и результаты из предыдущего сеанса камеры.

**Ограничение:** в реальном устройстве задержка и правильность сложных движений ещё не проверены; ограниченная камера или неполный кадр тела снижают точность. Отслеживание root translation и пальцев не добавлено.

## v0.6 — защита загруженного персонажа от неправильного Mocap (после теста APK №7)

Тест на пользовательском `GraffitiAlleyCat_rigged.glb` показал сильно сложенную позу после поднятия руки. Скриншот свидетельствует о деформации, но не позволяет доказать, виноват ли исходный skin weight или вычисление движений. Применены консервативные ограничения суставов **относительно исходной позы целевого GLB** — позвоночник, шея, таз, руки/локти, ноги/колени, кисти и стопы. Ограничения одинаковы в предпросмотре и экспортируемой анимации.

Исходный манекен также не получает нереалистичные повороты суставов из ошибочных landmarks. После 700 мс без уверенного отслеживания соответствующая кость плавно возвращается к исходной позе, а не остаётся навсегда вывернутой. Добавлена кнопка **«Сбросить позу»** рядом с загруженным GLB: она возвращает исходную позу и *замораживает* mocap. Та же кнопка превращается в **«Продолжить захват»**. Модель и запись не удаляются. Это позволяет отличить деформацию при захвате от проблем весов самого исходного рига.

**Важно:** режим безопасных ограничений предпочтительнее для тестирования на планшете, но пока ограничивает экстремальные наклоны корпуса и глубокие движения суставов. Это не гарантированное решение всех проблем риггинга или веса одежды; для доказательной диагностики деформаций нужны исходный GLB и видеозапись воспроизведения на устройстве. Надпись `MediaPipe GPU · основной поток` означает, что фоновый Worker v0.5 на устройстве не активировался — это отдельная задача по снижению задержки.

## v0.7 — стабилизация живого Mixamo-захвата (исправление причины, а не только ограничители)

На реальном планшете импортированный GraffitiAlleyCat скручивался при поднятии руки. Предыдущая схема сначала подгоняла пропорции тестового манекена к ориентирам MediaPipe, затем переносила его локальные повороты на другой GLB. При несовпадении осей костей это способно ломать позы даже у персонажей с Mixamo-именами.

**Новый путь для реальной камеры/видео с загруженным GLB:**
- Отдельный решатель `src/direct-mixamo.js` напрямую использует направленность сегментов MediaPipe и исходную позу костей загруженного персонажа (rest quaternion + дочерний сустав), вычисляет кратчайший swing без произвольного твиста.
- Калибрует поворот тела по плечевой оси GLB, учитывая модель, развёрнутую спиной к камере.
- Голова, торс, таз, плечевые пояса и стопы временно сохраняют исходную позу на **живом пользовательском GLB**, если кадр неполный/нестабильный. В надёжном режиме сейчас двигаются верхние/нижние сегменты обеих рук и ног; это намеренное ограничение для теста изолированной руки. Упрощённый тестовый манекен и демо работают прежним способом.
- Если ориентир руки теряется, двигается только эта рука, другие суставы не копируются; после паузы происходит плавный возврат.
- Исправлено несовпадение ключей в `relaxStaleBones`, из-за которого система могла тянуть суставы в нулевую позу даже при хорошем отслеживании.
- Запись теперь сохраняет как движения тестового манекена, так и *фактические локальные кватернионы загруженного GLB*. В предпросмотре и экспорте используются одинаковые повороты GLB; после экспорта возвращается фактическая поза, бывшая на экране.
- Регрессионные тесты на независимость двух рук, 180-градусное направление модели, пропавшую конечность и согласованность записи/воспроизведения.

**Не обещаем полностью отлаженный риг без реальной проверки:** некорректные веса skin, отсутствие дочерней кости, нестандартная ориентация персонажа, слабый свет или фронтальная камера с неполным обзором могут всё ещё вызывать искажения. Вся работа с медленным GPU-режимом WebView — отдельная проблема от правильности изгибов. В дальнейшем вернём безопасное движение торса и головы только после проверки движений рук.

## v0.8 — совместная проверка всего тела

Режим живой камеры/видео для импортированных Mixamo GLB расширен на **малые отклонения корпуса, шеи и головы**, сохраняя прямое управление обеими руками и ногами из v0.7. Первое уверенное положение плеч/таза и лицевых ориентиров задаёт базовую позу; далее вычисляются относительные наклоны (в пределах небольших углов). Для уменьшения скручивания движение торса распределяется по Spine1/Spine2, головы — по Neck/Head. Таз не переносится по сцене, так как MediaPipe Pose не даёт надёжной точной root translation из одной камеры. Кнопка **«Калибровать тело»** сбрасывает предыдущую базовую позу текущего GLB; после неё нужно встать прямо, руки опустить и дать камере увидеть плечи/таз/голову. Переключение источника автоматически сбрасывает эту калибровку.

Чтобы различить проблемы распознавания и GPU/CPU, интерфейс при fallback отображает **причину отказа фонового worker**, не скрывая использование основного потока. Это диагностическая информация, а не гарантированное устранение задержки Android WebView.

Тесты охватывают независимость конечностей, развёрнутые персонажи, наклоны корпуса и головы, пропадание ориентиров, ручную калибровку, согласованность записи и экспорта. Результат реального захвата на планшете пока не подтверждён. Если исходный GLB имеет неправильные skin weights, ограничение вращений не исправляет веса геометрии.
